# 参赛项目文件管理

本文件是本机项目管理 skill 的公开适配子集，不固定旧 HEAD 或硬件状态。适用于本项目；其他项目先读取自己的约束，不直接继承本项目单写入者或摘要策略。

1. 读仓库 `AGENTS.md`、[README](../../README.md)、[源码映射](../../docs/source-map.md)、[验证范围](../../docs/verification.md) 和 [许可范围](../../LICENSE_SCOPE.md)。按当前用户要求确定目标目录和操作范围；历史会话授权不自动恢复暂停。
2. 只读查实际 branch、HEAD、worktree、dirty 及目标文件；未查的远端/进程/硬件写未知。文件整理不触发项目 check/build/test 命令。
3. 写前列文件用途和保留方式。活文档用相对链接；未提交旧版若需保留先复制原字节，不能把 untracked 当已有 Git 历史。新附件用不存在的独立 run 目录，不覆盖旧实验。
4. 冻结源码、标签、manifest、bit/LTX、旧失败及未运行记录不就地改写。本项目不新增独立 hash 流程，使用已有 Git 对象和直接字节比较。原始摘要及检查基线保留。
5. 按“对象版本 / run ID / 工具配置 / 时间 / 实际结果 / 原始相对路径 / 存放位置 / 选择范围”编索引。公开选择集不称全量重跑包；源码、报告、生成物及真实硬件结论分别表述。
6. root 为唯一写入者，既有 reviewer 只读。提交、推送、合并依当前单独范围；不清理未知 dirty。凭据、机器身份、个人路径、完整厂商资料不放公开附件，删节需另作明确派生文件并保留原件。
7. 核对本轮差异、相对链接和保全情况；按用户要求只读后审。若交付入口变化，更新一次材料索引和限制；不另造多个“当前状态”，不自行恢复跳过项。

来源、适用/失效条件及实际检查见 [技能包索引](../README.md) 与 [协作案例 B](../../report/ai-collaboration.md)。
