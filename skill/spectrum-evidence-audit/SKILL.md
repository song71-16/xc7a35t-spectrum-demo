# 参数与图像证据核对

输入应为一个明确 run 的 JSON 和对应截图，先读 [现有字段示例](../../evidence/demo-loop-20261102-001/README.md)。允许离线读取、数字计算和图像检查；不调用接收脚本、真实 socket、Vivado 或硬件，不因缺证自动重测。

1. 从运行根而非 `interaction001` 短名字识别实验。记录源码/镜像基点、工具、日期、会话及覆盖范围，区分原文件与脱敏/提炼件；缺失即明确列出。
2. 检查 baseline、touch、PC 记录的 token 一致，state actual 和图像 metadata 的 epoch 相符，并与各自图像 source 配对。不要只看输入框或 APPLIED 字样。source 序号不能替代时间。
3. 单独检查 PC submission 的唯一性、接受状态、目标寄存器和值；ACK/write_receipt 的 sequence、intent、epoch 必须与 INFO 实际值及匹配配置的新图像相容。触控只有用户动作关联而无内部事务 ID 时，不声称精确内部因果追踪。
4. 所有时间差用同一主机单调时钟。提交到 ACK、INFO、图像均从该提交起算，不把累计值相加。图像观测含接收与 GUI 调度，不当作 FPGA 纯处理或触控物理时延。
5. 原始事件中观察到错误、断连或失败要按发生阶段保留；正常完成后 worker 停止产生的断连不能倒写成活动测试失败。协议状态不充分则结论为部分证据或 UNKNOWN，不补造缺项。
6. 比较幅度时保持频率和其他处理配置相同；理论幅度比可算 `20*log10(a2/a1)`，标明显示读数、理论值和外部仪器测量的区别。不要用不同频率的基线峰值代替同频幅度对照。
7. 帧计数分别注明 GUI 计数、回调日志条数和网络丢包含义，不强求不同层计数相等。单样本、短窗口及缺项如实报告；不外推分布、长稳、全按钮或完整生产速率。

输出一张“主张→文件/字段→计算→可支持范围→缺口”表。来源及已知失效条件见 [技能包索引](../README.md)；不修改旧 FAIL/PASS 或冻结版本。
