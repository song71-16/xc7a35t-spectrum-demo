# 参赛材料核对

该流程源于 [实际范围误判与纠正](../../report/ai-collaboration.md)，用于离线材料审查，不替代官方评分或法律判断。

1. 确认赛道、组别、指南版本及具体条款。用户未给的要求不凭经验补成硬性缺项，推荐目录、选用工具和可选加分分开记录。
2. 找到**实际提交对象**：报告中的仓库链接、公开整理树、固定标签和本地补充材料可能不同。先读 README 和许可范围、检查真实目录与 Git；不要拿内部开发树的中文文件名或 private 状态推断公开提交。
3. 打开已有报告，检查创新说明、对照表、资源时序、真实结果和引用。没有入库不等于没有写；写了不等于证据已随包提供；有位流不等于整体验收。
4. 建条款→报告位置→提交路径/版本→实际证据→剩余缺口表。新报告引用的实验按完整 run ID 配附件，不用旧标签中不同实验“代证”。无法读取某资料时写未核，不能断言不存在。
5. 核实际许可适用对象和第三方排除，保留署名和未核条款，不把根目录 MIT 当全仓库清权，不擅自改许可证解决缺项。
6. 发现自己前述结论不符时保留错误原句、触发证据、纠正和影响，撤回错误缺项；不伪造早期提示词或工具结果。
7. 分层交付：已完成材料、局部验证、未运行/待授权/需实物。仅提出最短必要动作，文件缺口不自动触发 EDA、重测、上传或新增功能。评分权重不是已得分数。

本仓库 [材料索引](../../report/README.md) 是一个实例，最终评分指南仍需由使用者提供。用相对路径、常规文件读取即可复用；新的赛道、证据格式或指南修订须重新解释。
